# Research index

This directory is the research. `../cluster/`, `../include/`, `../src/`, `../proto/`, and `../tests/` are the experimental system it runs on — infrastructure, not the contribution.

## The contract

**Research problem.** Approximate (ANN) indexes under replication have no observable correctness criterion — a degraded replica returns plausible-looking but wrong answers, with no error signal any existing checker can name.

**Research question.** Does node-failure chaos cause measurable, replica-level search-quality divergence in a replicated HNSW-based vector database; does that divergence persist after full cluster recovery; and can a ground-truth-free peer-agreement signal detect the degraded replica?

**Scope.** Single system (nano-db), single implementation, SIFT1M (~200K vectors) + synthetic `lowdim`/`uniform` controls, 2×3 topology, SIGKILL-based failure only, 5 seeds.

Full contract, current claim, non-claims, and required next experiments: see the top-level [`README.md`](../README.md#current-findings). Full prior-art positioning and what NOT to claim because someone else already owns it: [`RELATED_WORK.md`](RELATED_WORK.md).

| Can the per-replica protocol be applied to Weaviate? (instrument feasibility) | [`weaviate_probe/`](weaviate_probe/) | Method (pre-registered, #41) | **Closed — yes, by isolation probing, at a cost.** An isolated replica answers at `consistency_level=ONE` and reports a divergence it was shown (300 vs peers' 400), though Weaviate documents no node-targeting read. `/v1/nodes` `objectCount` lags by minutes and is not usable as `completeness`. | Can a Weaviate replica be read without stopping its peers? | [`weaviate_nonperturbing_probe/`](weaviate_nonperturbing_probe/) | Method (pre-registered, #43) | **Closed — yes for presence, no for search.** An undocumented cluster-internal API on `CLUSTER_DATA_BIND_PORT` returns one replica's own objects with peers up: 20/20 probes at 5s cadence vs the isolation probe's 1, and proven local (refuses when the node is down; returned 0 bytes while peers returned 31,190). `_search` 415s on 12 content types, so `index_recall` stays snapshot-only — the Weaviate experiment is asymmetric. Async repair converged in ~0.3s — *corrected by #48: one draw from a bimodal distribution, not a bound; see the repair-window row below* |
| Make the Weaviate per-replica probe trustworthy (per-id presence, digest pin) | [`weaviate_probe_per_id/`](weaviate_probe_per_id/) | Method (pre-registered, #46) | **Closed — both prerequisites met.** Ids are 16-byte big-endian in the internal payload, so presence is now a SET, not a byte count: 8/8 checks against a constructed expectation including 0 false positives on never-written ids; a diverged replica showed 0/10 peer-only ids while holding 20/20 others, peers up. Image pinned by digest. Also fixed a silent-topology hazard: `create_class` tolerated 422 and ran on a stale auto-schema class that was sharded (factor 1, 3 shards) rather than replicated |
| What makes Weaviate's async repair measurable? | [`weaviate_repair_window/`](weaviate_repair_window/) | Method (pre-registered, #48) | **Closed, then amended twice — read the amendments.** Repair is **independent of divergence size** across 50→5,000, so PR #44's "~0.3s" was one draw, not a bound. A randomized-delay test refutes warming (correlation with repetition index +0.373; the first run is among the fastest). ~~The latency is two discrete paths — nothing between 0.2s and 36s across 18 runs.~~ **Withdrawn 2026-09-06 (step 2c):** 18 runs at *fixed* timing offsets put **12 observations inside that interval**; the gap was a sampling artifact. What replaces it: holding the outage at 40s, a divergence ~38s old repairs in **~1s** while one ~6s old takes **~31s** — disjoint, exact p = 0.0022. The mechanism is *not* settled: measured from the **write** instead of the restart those conditions are 38.9s vs 36.9s, so "older divergence repairs faster" was withdrawn in review as an explanation and the measurement is reported without one; a 6s outage is bimodal (~0.02s or ~52s) and **unexplained**. The pre-registered binary statistic is **void** (its threshold assumed the gap). Sub-second sampling is still unnecessary: 1–5s cadence, ≥60s observation. Healing is a **step at 50–500 objects but a ~6s ramp at 5,000**, so size decides step-vs-curve. Probe bound: base64 ids work to 15,000, fail at 20,000 |
| Does `loo_agreement` detect the degraded replica on Qdrant? | [`loo_agreement_qdrant/`](loo_agreement_qdrant/) | Analysis (pre-registered, #52) | **Closed — yes for data loss, no for graph quality.** Scoring the pre-existing `_detection_stats()` metric over 51 already-committed runs (4,644 rows, **zero new compute**): against `e2e_recall` chaos scores **0.908** vs a **0.635** no-chaos control, p = 0.0023 — Layer 3 replicates on a second system. Against `index_recall` it collapses to **0.348 — the chance line is 0.333** — against a 0.670 baseline, separating at **p = 0.0001 in the wrong direction**: the detector is *at chance* at finding the replica behind this project's own headline Qdrant finding, and appears to be pointed at the data-poor replica instead. `completeness` is untestable — baseline is 100% tie-excluded because a healthy cluster has no worst replica. Condition is read from `run_meta.json`, not directory names, after review found `"chaos" in "nochaos"` had miscategorised five runs |

**Confirmatory** means the question and comparison design were fixed before the relevant run. **Exploratory** means the finding was noticed first and investigated after — reported as such rather than reframed as planned.
